Evaluation examples

  • Conflicting percentages must be flagged, not silently resolved.
  • A note with no numerical evidence should be marked unsupported.
  • Action items should keep a source ID where possible.
  • Human reviewers decide whether a claim is publishable.

Failure handling

  • Empty input → ask for source material.
  • Ambiguous figures → label for manual verification.
  • Rule misses context → show a limitation, not a confidence score.
  • Export or parsing issue → keep original notes available to the user.

Privacy boundary

  • No API request or server-side storage in this demo.
  • Do not paste confidential, sensitive or identifying data.
  • Clear the fields when finished, especially on a shared device.
  • A production version needs access controls and a retention policy.

How TraceNote works

Current implementation: all processing happens in this page using transparent JavaScript rules. It splits lines into source IDs, detects percentage strings, looks for unsupported or mismatched draft percentages, and extracts simple action phrases.

Proposed AI-enabled version: a language model could produce a structured summary and candidate citations, but a separate validation layer must verify that cited spans exist in the source and flag contradictory claims. Low-evidence or sensitive cases should be sent to a human reviewer.

Not implemented: live LLM calls, semantic entailment, PDF parsing, web fact-checking, authentication, or data storage. The demo intentionally makes no performance claim about those components.
